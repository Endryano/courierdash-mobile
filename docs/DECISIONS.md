# CourierDash Mobile — Decisions

## 2026-07-28 — Склад функціонального MVP

**Контекст.** Потрібно визначити переносимий з вебу scope без неузгодженого розширення.

**Рішення.** Annual Report входить у MVP. Garage, Expenses і transport rental не входять у MVP.

**Причини.** Це пріоритетні override-рішення власника продукту.

**Наслідки.** Roadmap містить Annual Report correctness та UI; Garage/expenses/rental не мають implementation-етапів MVP.

## 2026-07-28 — Фінансове представлення MVP

**Контекст.** Вебконтекст описує Netto/Tax як неостаточні та ризикові для перенесення.

**Рішення.** MVP використовує лише Brutto. Netto, Tax і податкові формули відкладені.

**Причини.** Пріоритетне рішення власника та відсутність затвердженої канонічної tax-формули.

**Наслідки.** Жоден MVP summary, chart або report не повинен видавати дохід після витрат чи податків за Netto.

## 2026-07-28 — Auth scope MVP

**Контекст.** Потрібен мінімальний безпечний auth flow, сумісний із Supabase.

**Рішення.** Email/password та email confirmation входять у MVP. Password Recovery, Google Sign-In і Apple Sign-In відкладені.

**Причини.** Пріоритетні override-рішення власника.

**Наслідки.** Email confirmation реалізується лише після окремого read-only аудиту production Supabase Auth; відкладені способи входу не проєктуються як активні UI flows.

## 2026-07-28 — Theme і localization

**Контекст.** Потрібні визначені межі першого native UI.

**Рішення.** MVP має тільки Dark Theme та локалізації `pl`, `uk`, `en`, `ru`.

**Причини.** Пріоритетні рішення власника; список мов підтверджено технічним контекстом вебверсії.

**Наслідки.** Light/system theme не реалізуються; весь перекладний UI і accessibility text повинні бути локалізовані.

## 2026-07-28 — Work validation і calendar policy

**Контекст.** Потрібно усунути неоднозначності веблогіки перед calculation core.

**Рішення.** Від'ємні Work-значення заборонені; однаковий start/end означає 0 годин; перерви з перетином або поза межами зміни блокуються. Дата зміни зберігається як локальний `YYYY-MM-DD` без UTC-конвертації; тиждень триває з понеділка до неділі.

**Причини.** Пріоритетні рішення власника.

**Наслідки.** Validation і pure calculations мають бути протестовані за цими правилами; напівзаповнену перерву не можна зберегти, а розрахований результат годин не може бути від'ємним; дані не нормалізуються мовчки.

## 2026-07-28 — Навігація та foundation

**Контекст.** Потрібно почати проєкт поетапно, не фіксуючи непогоджений UX.

**Рішення.** Onboarding входить у MVP, але не блокує foundation. Остаточний bottom tabs layout не погоджений.

**Причини.** Пріоритетні рішення власника.

**Наслідки.** Foundation не приймає незворотних навігаційних рішень; tab structure потребує окремого погодження.

## 2026-07-28 — Expo foundation technology

**Контекст.** Потрібна мінімальна, офіційно підтримувана база для Android та iOS без реалізації продуктового UI.

**Рішення.** Foundation використовує Expo SDK 57, Expo Router і структуру `src/app/` з routes `_layout.tsx` та `index.tsx`.

**Причини.** Це погоджений foundation scope та актуальний шлях, рекомендований Expo для нового TypeScript-проєкту.

**Наслідки.** Tabs, auth, Supabase, theme, localization і tests не входять до foundation; вони реалізуються лише на наступних окремо погоджених етапах.
